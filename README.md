# Account Pulse

**Technical Account Operating System**

**From client conversations to verified execution.**

> **Nothing falls through the cracks.**

Account Pulse is a polished, interactive product prototype built to demonstrate how I think about Technical Account Management: turning account signals, client conversations, operational data and follow-ups into visible ownership and verified outcomes.

## Live Demo

**https://hemanthyadv.github.io/account-pulse-tam/**

The application is deployed through **GitHub Actions + GitHub Pages**.

## What the product demonstrates

- Executive account health with explainable drivers
- Action tracking from creation through verified closure
- Data integrity and source-of-truth workflows
- Human verification before operational changes
- Documentation and compliance tracking
- Meeting → decision → action → owner → deadline → verification
- Proactive risk identification
- Stakeholder context
- Reusable operational playbooks
- Communication workflows
- Presentation / interviewer walkthrough mode

## Account Pulse operating model

```
UNDERSTAND
    ↓
VERIFY
    ↓
ORGANIZE
    ↓
ASSIGN
    ↓
COMMUNICATE
    ↓
FOLLOW UP
    ↓
CLOSE
    ↓
LEARN
```

The product's core execution framework is:

```
SIGNAL → CONTEXT → DECISION → OWNER → DEADLINE → VERIFICATION → OUTCOME
```

## Human verification

The prototype deliberately separates an automated signal from a business decision:

```
AUTOMATED SIGNAL
      ↓
HUMAN VERIFICATION
      ↓
ACTION
      ↓
VERIFIED OUTCOME
```

This reflects a practical approach to responsible automation: systems can surface discrepancies, while people validate context and accountability before changes are finalized.

## Why I built it

I built Account Pulse as a practical demonstration of how I would approach the operational side of Technical Account Management: keeping information accurate, making ownership visible, communicating clearly, identifying risks early, and following commitments through to verified closure.
